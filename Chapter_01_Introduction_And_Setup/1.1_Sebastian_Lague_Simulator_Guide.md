# 🕹️ 1.1 Sebastian Lague Simulator Mechanics Guide

Before we start wiring up complex logic, it is crucial to understand how Sebastian Lague's *Digital Logic Simulator* works. 

This software is brilliant for its simplicity—it allows you to abstract complex circuits into custom "chips"—but it has a few specific quirks, hotkeys, and limitations you need to know to avoid frustrating bugs.

---

## 🎮 Navigation & Hotkeys

The simulator features a minimalist UI. Mastering the controls early will speed up your workflow significantly.

* **Pan/Move Canvas:** Right-Click + Drag or Middle-Mouse + Drag.
* **Zoom:** Mouse Scroll Wheel.
* **Select Area:** Left-Click + Drag to create a selection box.
* **Delete Component/Wire:** Select the item(s) and press `Backspace` or `Delete`.
* **Copy/Paste:** `Ctrl + C` to copy a selection, `Ctrl + V` to paste.

---

## 🔌 Wiring & Pin Mechanics

Wiring is straightforward, but the simulator has specific rules on how signals flow.

* **Making Connections:** Click and drag from an output pin (usually on the right side of a chip) to an input pin (usually on the left). 
* **Wire Branching:** You can pull multiple wires from a single output node to feed different gates. 
* **Wire Colors:** Right-click on any wire to change its color! This is **highly recommended** for keeping track of complex circuits.
  * *Tip:* In this handbook, we generally use **Red** for Clock signals, **Blue** for Control lines, and **Green/Default** for Data.
* **Input Collisions (WARNING):** If you route two active output wires into the *same* input pin, the simulator does not know which signal to trust, and the state will behave randomly or glitch. To safely merge signals onto a single wire, use a **Tri-State Buffer** or a **Multiplexer (MUX)**.

---

## 📦 Packaging Custom Chips

The most powerful feature in this simulator is the ability to turn a messy web of gates into a clean, reusable microchip. This is how we climb the ladder of abstraction.

### How to Create a Chip:
1. **Place Input & Output Nodes:** Drag the generic `INPUT` and `OUTPUT` blocks from the bottom menu onto your canvas.
2. **Name Your Pins:** Click on the text label of the Input/Output nodes and name them (e.g., `A`, `B`, `Carry_In`, `Sum`). These names will appear on the final chip.
3. **Wire the Logic:** Connect your inputs, gates, and outputs.
4. **Package It:** Click the **"Create Chip"** (or package) button in the UI. 
5. **Name the Chip:** Give it a clear name (e.g., `8-Bit_Adder`) and choose a color for its block.
6. **Reuse:** The new chip will now appear in your library menu, ready to be dropped into new projects!

*Note: Once a chip is packaged, it acts as a black box. In newer versions of the simulator, you can right-click a custom chip to "View Internal State" during runtime to monitor signal flow.*

## ⚠️ Known Quirks & Limitations

Keep these in mind when debugging:

* **Propagation Delay:** In real life, electricity takes time to travel through gates. The simulator processes signals almost instantly, but complex feedback loops (like Latches or Flip-Flops) can sometimes cause infinite loops or crash the simulation if there is no delay. 
* **Clock Speeds:** Built-in Clock chips toggle constantly. If a circuit isn't updating correctly, try manually toggling an input button instead of using an automated clock while you test your logic.
* **Floating Pins:** Unlike real life, unconnected input pins in this simulator default to `0` (Off). However, it is good practice to explicitly wire unused inputs to an OFF state if a specific chip requires it.

---

## 📝 Best Practices for the Handbook

When building components from this repository:
1. **Build Left to Right:** Keep inputs on the left and outputs on the right. This makes circuits readable.
2. **Double Check Before Packaging:** Before creating a custom chip, toggle every possible input combination to ensure the outputs match the Truth Tables provided in this handbook. If you package a broken chip, every larger system that uses it will break!
