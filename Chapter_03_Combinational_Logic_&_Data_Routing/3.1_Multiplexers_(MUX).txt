# 3.1 Multiplexers (MUX)

A **Multiplexer** (often abbreviated as **MUX**) is a foundational digital circuit that acts as a digitally controlled multi-position switch. Its primary function is to receive multiple input data streams and route exactly one of them to a single output line, based on the binary value of a set of "selector" or "control" pins.

In computer architecture, multiplexers are the ultimate traffic controllers. They dictate which memory bank sends data to the processor, which register feeds into the Arithmetic Logic Unit (ALU), and which peripheral gets access to the main system bus.

Mathematically, a MUX with $n$ selector lines can control up to $2^n$ data inputs.

---

## 3.1.1 Basic 2-to-1 MUX

The 2-to-1 Multiplexer is the smallest possible routing unit. It features two data inputs ($D_0$ and $D_1$), a single selector input ($S$), and one output ($Y$).

When the selector is `0`, the MUX connects the output to $D_0$. When the selector is `1`, the MUX connects the output to $D_1$.

### Truth Table

| Selector ($S$) | Input $D_0$ | Input $D_1$ | Output ($Y$) |
| --- | --- | --- | --- |
| 0 | 0 | X (Don't Care) | **0** |
| 0 | 1 | X (Don't Care) | **1** |
| 1 | X (Don't Care) | 0 | **0** |
| 1 | X (Don't Care) | 1 | **1** |

### Boolean Algebra Derivation

Using the Sum-of-Products (SOP) method from the truth table, the output is true if:

1. Selector is `0` AND $D_0$ is `1`  $\rightarrow (\overline{S} \cdot D_0)$
2. Selector is `1` AND $D_1$ is `1`  $\rightarrow (S \cdot D_1)$

**Final Equation:**


$$Y = (\overline{S} \cdot D_0) + (S \cdot D_1)$$

### 🔹 Method 01: Standard Logic Gates

This is the universally compatible, classical method of building a MUX out of primitive logic gates (AND, OR, NOT). It translates the boolean equation directly into hardware.

* **Wiring Guide:**
1. Pass the Selector ($S$) through a **NOT gate** to create $\overline{S}$.
2. Feed $\overline{S}$ and Data $D_0$ into **AND Gate 1**. This creates a "gate" that only lets $D_0$ pass when $S$ is `0`.
3. Feed the original Selector $S$ and Data $D_1$ into **AND Gate 2**. This creates a "gate" that only lets $D_1$ pass when $S$ is `1`.
4. Connect the outputs of both AND gates into a final **OR Gate**. Since $S$ cannot be `0` and `1` simultaneously, only one AND gate will ever output data at a time. The OR gate simply funnels the active signal to the final output.


* **Gate Depth:** 3 levels (Inverter $\rightarrow$ AND $\rightarrow$ OR).
* **Pros & Cons:** It is highly reliable and easily simulated in basic software, but introduces a non-trivial propagation delay due to the signal passing through three distinct layers of silicon.

### ⚡ Method 02: Tristate-Optimized Routing

Modern hardware and advanced simulators use a more physics-based approach utilizing **Tri-state Buffers**. A standard logic gate can only output `1` (High Voltage) or `0` (Low Voltage). A Tri-state Buffer adds a third state: **High-Impedance (High-Z)**, which physically disconnects the wire from the circuit like an open mechanical switch.

* **Wiring Guide:**
1. Attach Data $D_0$ to Tri-state Buffer 0. Connect its "Enable" pin to an inverted Selector ($\overline{S}$).
2. Attach Data $D_1$ to Tri-state Buffer 1. Connect its "Enable" pin to the standard Selector ($S$).
3. **Tie both outputs directly together** into a single wire ($Y$).


* **Gate Depth:** 1 to 2 levels.
* **Why it is superior:** Normally, tying two outputs together causes a catastrophic short-circuit. However, because $S$ and $\overline{S}$ are mutually exclusive, one buffer will actively transmit data while the other enters the High-Z state (disconnecting itself). This eliminates the need for the final OR gate, drastically reducing silicon area, lowering power consumption, and increasing clock speed limits.

## 3.1.2 Cascaded 4-to-1 MUX

A 4-to-1 MUX selects between four distinct data inputs ($D_0$ through $D_3$). Because there are four possible sources, the circuit requires **two selector lines** ($S_1$ acting as the High Bit, and $S_0$ acting as the Low Bit) to count from binary `00` to `11`.

**The Naive Approach vs. Cascading:**
You *could* build a 4-to-1 MUX using a massive four-input OR gate and four 3-input AND gates. However, hardware engineers rarely do this because large gates suffer from "Fan-in" limits (physical electrical degradation). Instead, the standard industry practice is to build a **binary tree** out of smaller 2-to-1 MUXes.

**Building the Cascade Tree:**
You will need three 2-to-1 MUX components to build a single 4-to-1 MUX.

1. **Stage 1 (The Base Layer):**
* **MUX A:** Receives $D_0$ and $D_1$. Its selector pin is wired to the Low Bit ($S_0$).
* **MUX B:** Receives $D_2$ and $D_3$. Its selector pin is also wired to the Low Bit ($S_0$).


2. **Stage 2 (The Apex Layer):**
* **MUX C:** Receives the outputs of MUX A and MUX B. Its selector pin is wired to the High Bit ($S_1$).



**How it routes data:**
If your selector bits are `10` ($S_1=1, S_0=0$):

* Stage 1 receives $S_0=0$. MUX A passes $D_0$ upward. MUX B passes $D_2$ upward.
* Stage 2 receives $S_1=1$. MUX C looks at its two inputs and chooses the second one (which came from MUX B).
* **Result:** Data $D_2$ is successfully routed to the output.

## 3.1.3 8-Bit Wide Bus MUX

Until now, the MUX has routed single-bit wires (a single `1` or `0`). However, a functional CPU does not move data one bit at a time. It moves data in blocks called **Buses** (e.g., an 8-bit byte, a 32-bit word, or a 64-bit vector).

To choose between routing the 8-bit output of an ALU **OR** the 8-bit output of the RAM into a CPU Register, we must use an **8-Bit Wide Bus MUX**.

**The Architecture:**
Scaling up to bus-width does not require any new boolean logic; it requires **parallelism**. An 8-Bit Bus MUX is literally just eight separate 2-to-1 multiplexers arranged in a stack, operating simultaneously.

* **The Data Inputs:** You have two buses, Bus A and Bus B, each containing 8 wires (Bits 0 through 7).
* **The Parallel Array:**
* MUX 0 handles Bit 0 of Bus A and Bit 0 of Bus B.
* MUX 1 handles Bit 1 of Bus A and Bit 1 of Bus B.
* ...this pattern continues up to MUX 7.


* **The Unified Selector:** The most critical feature is the selector wire. There is still only **one** selector wire ($S$). This single wire is split and connected to the selector pins of all 8 parallel MUXes simultaneously.
* **The Result:** When the CPU sets $S=0$, all eight MUXes simultaneously switch to their top input, allowing the entirety of Bus A to flow to the output bus in perfect synchronization.

This parallel array is the fundamental mechanism that allows a processor's control unit to physically manage the flow of complex data packets across the motherboard.
