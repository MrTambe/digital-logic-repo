# ⚙️ 4.6 Full 8-Bit ALU Sub-System

Up to this point, we have designed isolated circuits that perform specific tasks: adders, subtractors, and basic logic gates. However, a CPU cannot physically rewire itself every time a programmer wants to switch from addition to subtraction. 

The solution is the **Arithmetic Logic Unit (ALU)**. The ALU acts as the central processing hub of the CPU. It wires all mathematical and logical circuits in parallel, feeds the operands ($A$ and $B$) into all of them simultaneously, and uses a **Multiplexer (MUX)** to selectively route only the desired answer to the final output.

---

## 🔹 4.6.1 Design 01: Basic Calculator ALU 

A basic ALU requires an **Opcode (Operation Code)** to know what task to perform. For a 4-function ALU (ADD, SUB, AND, OR), we need a 2-bit control wire (which we will call $Op[1:0]$) to control a 4-to-1 Multiplexer.

## ⚡ 4.6.2 Design 02: Extended Flag ALU

Calculating the mathematical result is only half of the ALU's job. To allow a computer to make decisions (like `if x == 0` or loops), the ALU must also report the **Status Flags** of the math it just performed. 

These flags are single-bit wires pushed out of the ALU and stored in a special CPU register (the Status Register) so the Control Unit can read them on the next clock cycle. The three most critical flags are **Zero (Z)**, **Carry (C)**, and **Overflow (V)**.

      <b>1. The Zero Flag (Z):</b><br>
      Asserts `1` if the entire 8-bit result is exactly `00000000`. This is heavily used for equality checks (e.g., if $A - B$ results in Zero, then $A$ must equal $B$).
      <ul>
        <li><b>Hardware:</b> A massive 8-input <b>NOR gate</b> attached to $Result[7:0]$. If any bit is a `1`, the NOR outputs `0`. If all bits are `0`, the NOR outputs `1`.</li>
      </ul>
      <br>
      <b>2. The Carry Flag (C):</b><br>
      Asserts `1` if an addition exceeded 255 (the max capacity of an 8-bit unsigned integer). Used to chain multiple 8-bit additions together to do 16-bit or 32-bit math.
      <ul>
        <li><b>Hardware:</b> Directly wired to the $C_{OUT}$ pin of the final Full Adder (Bit 7) in the arithmetic block.</li>
      </ul>
      <br>
      <b>3. The Overflow Flag (V) — Signed Math Error:</b><br>
      While Carry (C) detects errors in <i>unsigned</i> math, Overflow (V) detects errors in <i>signed 2's Complement</i> math (where numbers range from -128 to +127). An overflow occurs if adding two positives yields a negative, or adding two negatives yields a positive.
      <ul>
        <li><b>Hardware:</b> We monitor the Carry going <i>into</i> the Most Significant Bit ($C_7$) and the Carry coming <i>out</i> of the Most Significant Bit ($C_8$). If they do not match, an Overflow occurred. </li>
        <li><b>Equation:</b> $V = C_7 \oplus C_8$ (Using an XOR gate).</li>
      </ul>

### 💡 The Big Picture: How Flags Drive Software
When you write code like `if (A > B) { doSomething() }`, the compiler turns that into two assembly instructions:
1. `CMP A, B` (The ALU secretly performs $A - B$ using the Subtractor block but throws away the result, keeping only the flags).
2. `JGT doSomething` (Jump if Greater Than). The CPU checks the flags. If the **Zero Flag (Z)** is `0` and the **Carry/Borrow Flag (C)** is `0`, it knows $A$ was greater than $B$, and triggers the code block.
